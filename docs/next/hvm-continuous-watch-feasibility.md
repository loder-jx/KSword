# Continuous Watch 可行性研究（issue #195 P2）

本文回答一个问题：**在 KSword 现有的 R-1 层上，能不能把内存监视从「下一次访问」
推进到「每一次访问」，而不降低正确性要求。**

issue 第二十三节给 P2 定了四条准入门槛，四条全过才允许增加 `Mode = CONTINUOUS`：

1. 不破坏来宾的调试语义；
2. 支持 SMP；
3. 在 nested Hyper-V 上能工作；
4. 不制造不可控窗口。

结论写在最前面：

> **四条方案里没有一条同时过这四关。** 其中一条（EPT 执行视图翻转）过三关且第四关
> 可控，但它只覆盖**执行**，不覆盖读写；另外三条各自被一条硬约束挡死，且那条约束
> 不在我们这一侧。
>
> 因此本轮**不增加** `Mode = CONTINUOUS`。P0 的 `FIRST_TOUCH` 保持为唯一模式。
> 真要做，可做的是一个**范围受限**的变体（仅执行、仅本机支持 MTF 时、或按页
> 采样），它值不值得单独立项由需求决定，而不是由「界面上少一个选项」决定。

---

## 一、判据从哪来

这四条门槛不是抽象原则，每一条都对应一次已经付过代价的故障：

| 门槛 | 对应的真实故障 |
| --- | --- |
| 不破坏调试语义 | 来宾自己的 `#DB`／`DR7` 被我们占用之后，来宾调试器行为变化，而它没有任何办法察觉 |
| 支持 SMP | `ALLOW_ONCE` 的放宽窗口在共享 EPT 层次下是**全机可见**的：一个核放宽，另一个核同一刻读到的就是放宽后的视图 |
| nested Hyper-V 可工作 | 靶机实测缺 MTF。整个 `WATCH_ONCE` 语义就是为了绕开这一条才存在的 |
| 不制造不可控窗口 | 「先恢复权限、再单步、再撤回」这三步之间目标页是**完全开放**的，而这段窗口的长度由中断与调度决定，不由我们决定 |

第四条值得单独说明。SDM 28.5.2 明确：MTF 保证的是「下一个指令边界」，不是「下一条
你想要的那条指令」——中断先于目标指令投递时，MTF exit 落在 ISR 的第一条指令之后。
HyperDbg 的源码注释里有同一现象的原话记录：执行耗时过长时执行流会切到别的例程，
MTF 在别的例程上结束，然后同一条指令很快（而且一定会）再次触发。也就是说，那段
「完全开放」的窗口不但存在，长度还不受控。

---

## 二、逐条评估

### 方案 A：MTF（Monitor Trap Flag）单步重放

经典实现：EPT violation → 恢复权限 → 置 MTF → VMRESUME 执行一条指令 → MTF exit →
撤回权限 → INVEPT。HyperDbg 的 `!epthook`、illusion-rs 都是这个模型。

| 门槛 | 判定 | 依据 |
| --- | --- | --- |
| 调试语义 | **过** | MTF 是 VMCS 属性，来宾看不见，不占用 DR 寄存器也不改 `RFLAGS.TF` |
| SMP | **有条件过** | MTF 是「当前 VMCS / 当前逻辑处理器」的属性，不是全局属性。但**权限恢复不是**：共享 EPT 层次下恢复一次全机可见。要过这一关必须每核私有 EPT 层次或走 EPTP 切换，我们两样都有 |
| nested Hyper-V | **不过** | 靶机实测不给 MTF。这是硬阻断，且不在我们这一侧 |
| 不可控窗口 | **不过** | 见上：中断投递会把 MTF 落到 ISR 里；SDM 28.5.2 还列了 MTF **根本不发生**的条件（到达 pending 边界前发生了别的 VM exit、处理器进入 shutdown 或 wait-for-SIPI）。那时页面永久停在开放状态——不是「窗口长了一点」，是窗口不关了 |

两关不过。第三关的阻断是环境的，第四关的阻断是架构的：**即使换一台给 MTF 的机器，
第四关仍然不过**，只能靠「在其它退出路径上做兜底恢复」把损害限制住，而那是补救，
不是满足门槛。

另外两条 MTF 自带的语义坑，一并记在这里，因为它们会直接毁掉读数：
`rep movsb` 每次迭代都产生 MTF（不是整条指令一次），而完整性扫描恰恰爱用它；
`XBEGIN` 的 MTF pending 在 fallback 地址上。

### 方案 B：来宾 `RFLAGS.TF` + 拦截 `#DB`

用来宾自己的单步标志代替 MTF：恢复权限的同时置 `TF`，靠 exception bitmap bit 1
把 `#DB` 拦下来，在 `#DB` 处理里撤回权限。

| 门槛 | 判定 | 依据 |
| --- | --- | --- |
| 调试语义 | **不过** | `TF` 和 `DR6`／`DR7` 是**来宾可见**的架构状态。来宾读 `RFLAGS` 能看见我们置的 `TF`；来宾自己在单步时我们会吞掉它的 `#DB`；`DR6` 的 `BS` 位会被我们污染。这不是「可能被检测到」，是我们直接改变了来宾程序的可观测行为 |
| SMP | 同 A | 权限恢复仍然是全机可见的那一步 |
| nested Hyper-V | **过** | `#DB` 拦截不需要外层给任何特殊能力 |
| 不可控窗口 | **不过** | 与 A 同源，且更糟：`#DB` 的优先级低于中断，窗口更容易被撑开；来宾若把 `TF` 清掉（一次 `popfq` 就够），撤回点永远不到 |

第一关就出局。这一条被 issue 自己点名列进 P2 待评估，评估结果是：**它与第一条门槛
直接矛盾**，不是实现难度问题。

### 方案 C：有界指令模拟

不放行原指令，而是在 VMX root 里解码并模拟它，然后推进 RIP。权限一次都不用放开，
窗口问题从根上消失。

| 门槛 | 判定 | 依据 |
| --- | --- | --- |
| 调试语义 | **过** | 来宾看不见任何东西 |
| SMP | **过** | 页面权限自始至终没变过，不存在放宽窗口 |
| nested Hyper-V | **过** | 不依赖任何 VMX 可选能力 |
| 不可控窗口 | **过** | 没有窗口 |

四关全过——代价在别处：**它要求一个正确的 x86 内存访问解码器**，而 issue 第二十节
明确把「完整 x86 指令模拟器」排除在本议题之外。

这条排除是对的，理由不是工作量：一个**不完整**的模拟器比没有模拟器危险得多。
模拟错一条指令的后果不是报错，是来宾在一个被悄悄改过的寄存器或内存上继续跑下去；
而它错在哪一条，只有等到某个具体程序在某台具体机器上崩掉时才知道。要覆盖的不只是
`mov`：`movs`／`stos`／`cmps` 带 `rep` 前缀、锁前缀的读改写、`xchg`、`cmpxchg16b`、
非时序存储、AVX 的宽访问、跨页访问、段前缀、地址大小前缀，每一条都得对。

**如果**要往这个方向走，可行的是**有界**变体：只模拟一个**白名单**指令集合，
遇到白名单外的指令就退回 `FIRST_TOUCH` 语义（记一次命中、永久放行、报告
「这条监视因为遇到不支持的指令而降级」）。这样错误模式从「静默算错」变成「明确
降级」，而后者是可以接受的。这是本文四条里**唯一**有出路的一条，出路的名字是
「范围受限 + 显式降级」，不是「做一个完整的模拟器」。

### 方案 D：EPT 执行视图翻转（无 MTF 的连续执行追踪）

两张 EPT 视图：视图一里目标页不可执行、其余可执行；视图二里目标页可执行、其余
不可执行。执行进入目标页时在视图一上违规 → 切到视图二；执行离开目标页时在视图二
上违规 → 切回视图一。**每一次进入和离开都产生一次退出，而且不需要单步。**

这正是 `MemoryMon` 那一类模型，我们也已经有跑通的 EPTP 切换后端（见
`EPT切换后端设计.md`，实机验证过分离视图在缺 MTF 的嵌套靶机上真的生效）。

| 门槛 | 判定 | 依据 |
| --- | --- | --- |
| 调试语义 | **过** | 来宾完全看不见 |
| SMP | **过** | 视图选择是 per-vCPU 状态（EPTP 在各自的 VMCS 里），翻转不再是全局可见事件 |
| nested Hyper-V | **过** | EPTP 切换后端已在靶机上实测可用 |
| 不可控窗口 | **过** | 任一时刻两张视图都是完整合法的，不存在「目标页开放着」的中间态 |

四关全过。**但它只回答执行。**

这一点不是实现取舍，是机制本身的边界：视图翻转的回切触发点，靠的是「执行离开了
目标页」这个事件，而**数据访问没有对应的事件**——读写一页之后处理器不会再产生
第二次违规告诉你「读完了」。secret.club 对 `matrix-rs` 的评价说的是同一件事：
纯 EPTP 切换而不单步，处理不了同页 RWX 混合访问模式。

代价还有两条要摆在明面上：

- **每一次跨页控制转移都要退出一次。** 目标页在热路径上时这是持续的性能负担，
  不是一次性的。
- **视图二里「其余页不可执行」意味着整张表要维护两份权限。** 页数多起来之后，
  这两份之间的任何不一致都是 EPT misconfiguration 或静默漏抓。

## 三、汇总

| 方案 | 调试语义 | SMP | nested Hyper-V | 无不可控窗口 | 覆盖 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| A. MTF 单步重放 | 过 | 有条件过 | **不过**（靶机无 MTF） | **不过**（SDM 28.5.2） | R/W/X | 否 |
| B. 来宾 TF + `#DB` | **不过**（改变来宾可观测状态） | 有条件过 | 过 | **不过** | R/W/X | 否 |
| C. 完整指令模拟 | 过 | 过 | 过 | 过 | R/W/X | 被 issue 第二十节排除；有界变体是唯一出路 |
| D. EPT 执行视图翻转 | 过 | 过 | 过 | 过 | **仅 X** | 唯一四关全过，但答不了读写 |

## 四、本轮的决定

**不增加 `Mode = CONTINUOUS`。**

理由不是「还没做完」，而是没有一条路径能在不降低正确性要求的前提下提供 issue 所说的
「每一次访问都产生事件」。issue 自己写的那句话在这里成立：

> 不能为了 UI 上多一个 Continuous 选项而降低正确性要求。

同时记下两条**可以**立项的东西，它们的共同点是**范围如实写在名字里**，不冒充
通用的连续监视：

1. **`Mode = CONTINUOUS_EXECUTE`（方案 D）。** 只答「这一页被执行了多少次、每次从
   哪里进来」。四关全过，后端已有。它答不了写入，所以不能叫 Continuous Watch，
   必须在界面上叫「连续执行追踪」，并且与内存监视分开摆——名字里含糊一次，用户就
   会拿它去等一个永远不会来的写入事件。
2. **有界模拟 + 显式降级（方案 C 的受限变体）。** 白名单内的访问连续监视，白名单外
   立刻降级成一次性并**报告降级**。这条的门槛不在机制上，在于白名单必须被穷举验证
   ——而验证方法现成：`KswordARKLightTests` 里已经有一套针对纯模块的穷举测试。

两条都需要独立立项与独立验收，不搭在 issue #195 上。

## 五、本文用到的实测与规范来源

- 靶机缺 MTF：`KSWORD_ARK_HVM_FEATURE_MONITOR_TRAP_FLAG` 能力位在 2-vCPU nested
  Hyper-V 靶机上为零。这是 `WATCH_ONCE` 存在的全部理由，也是本文方案 A 的硬阻断。
- SDM 28.5.2 Monitor Trap Flag：MTF pending 的时机、与事件投递的交互、`rep` 串指令
  每次迭代都 pending、以及 MTF **不发生**的四种条件。
- SDM 31.3.3.1 EPT Misconfigurations：`R=0 & W=1` 非法，execute-only 是可选能力。
  这是「请求只监视读必然连带监视写」的架构根据，也是内存监视界面必须并排显示
  requested / effective 两栏的原因。
- HyperDbg `Hv.c` 的 `HvEnableMtfAndChangeExternalInterruptState`：置 MTF 的同时
  打开 external-interrupt exiting、关掉 interrupt-window exiting，注释明确说明是因为
  MTF 会在别的例程上结束并导致同一条指令重复触发。
- secret.club《Hypervisors for Memory Introspection and Reverse Engineering》：
  `illusion-rs`（每核 EPT + MTF 重放）与 `matrix-rs`（共享双 EPT + EPTP 切换）的
  对比；明确指出纯切换模型处理不了同页 RWX 混合访问。
- 本仓库 `docs/next/EPT切换后端设计.md` 与 `docs/next/隐蔽Hook安全边界决策.md`：
  EPTP 切换后端在缺 MTF 的嵌套靶机上实测生效，以及「写叶 + MTF」与「切 EPTP」两种
  后端在安全边界上并无差别这一结论。
- 完整规范摘录见 `docs/虚拟化规范要点.md`。
